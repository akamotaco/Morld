# 챕터 1 구현 계획: 숲속 저택 — 알파 달성

> **목표**: 플레이어가 숲속 저택의 '알파' 지위를 획득하면 챕터 1 종료
> **두 갈래**: 신뢰 루트 / 굴복 루트 (혼합 가능)

---

## 핵심 원칙: 이주 안전성

> **특정 location ID에 특화된 행동 패턴/로직 금지.**
> 이주해도 생활 패턴이 깨지지 않아야 함.
>
> - 생활 공간 탐색: `_home_region` (bed_owner prop 기반, 동적)
> - 시설 탐색: `facility_resolver` (prop 기반, 동적)
> - 보관소 탐색: `resolve_storage_container` (storage:{category} prop 기반, 동적)
> - 취침 장소: bed_owner:{name} prop 기반 (ID 의존 허용 — 반드시 할당되어 있으므로)
>
> 새 퀘스트/이벤트에서 location 참조 시 반드시 prop 기반 또는 unique_id 기반으로 탐색할 것.

## Phase 1: 일일 퀘스트 풀

### 목표
세라가 매일 아침 플레이어에게 심부름을 부여. 완료 시 신뢰+1, 실패/무시 시 신뢰-1.

### 구현 항목
- [ ] 일일 퀘스트 데이터 정의 (6~8개 풀)
- [ ] 세라 talk()에서 "오늘 할 일" 분기 추가
- [ ] 퀘스트 미완료 시 자정에 신뢰 -1 처리
- [ ] 퀘스트 완료 보상: 신뢰 +1 (+ 선택적 아이템)

### 퀘스트 풀 (예시)

| ID | 이름 | 조건 | 난이도 |
|----|------|------|--------|
| daily_gather_herb | 약초 채집 | collect: herb × 3 | 쉬움 |
| daily_gather_berry | 열매 채집 | collect: berry × 5 | 쉬움 |
| daily_firewood | 장작 모으기 | collect: branch × 5 | 보통 |
| daily_fishing | 낚시 | collect: fish × 2 | 보통 |
| daily_patrol | 숲 순찰 | reach: 숲 외곽 3곳 | 보통 |
| daily_clean | 저택 청소 | 청소 행동 3회 | 쉬움 |
| daily_hunt | 사냥 | defeat: 야생동물 1마리 | 어려움 |
| daily_delivery | 물자 전달 | deliver: 특정 아이템 to 밀라 | 쉬움 |

### 세라 일일 퀘스트 부여 로직
```
매일 아침 (스케줄 or on_time_elapsed):
  1. 전날 퀘스트 미완료 → 신뢰 -1
  2. 풀에서 랜덤 1개 선택 (이전과 중복 방지)
  3. 퀘스트 AVAILABLE로 설정

퀘스트 전달 방식 (2가지 경로):
  A. 세라가 플레이어를 찾아옴 (능동적)
     - seek_player 인프라 활용 (스케줄에 "심부름 전달" 활동 추가)
     - on_meet 시 일일퀘스트 대화 자동 시작
     - "오늘 할 일이 있어. 따라와." 느낌
  B. 플레이어가 세라에게 먼저 가서 "심부름" 액션으로 받기
     - 기존 errand 인프라 그대로 활용
```

### 체크리스트
- [ ] 퀘스트 풀 데이터 작성 (sera.py CHARACTER_QUESTS)
- [ ] 모든 퀘스트 repeatable=True, category="daily"
- [ ] 세라 talk()에서 일일퀘스트 제안 분기
- [ ] 미완료 패널티 로직 (on_time_elapsed 자정 체크)
- [ ] 완료 보상에 신뢰 +1 포함
- [ ] 중복 선택 방지 (이전 퀘스트 ID 기억)
- [ ] 6개 이상 퀘스트가 돌아가는지 3일 이상 테스트

### 테스트
```
1. 세라에게 말 걸기 → 일일퀘스트 부여 확인
2. 퀘스트 완료 → 신뢰 +1 확인
3. 퀘스트 무시하고 자정 → 신뢰 -1 확인
4. 다음 날 → 새 퀘스트 부여 확인 (중복 아닌지)
5. 3일 연속 완료 → 신뢰 누적 확인
```

## Phase 2: 캐릭터 태도 분기 (호감/신뢰 기반)

### 목표

### 구현 항목

#### 세라 태도 단계
| 신뢰 | 호감 | 태도 |

| 40~60 | 편안해짐, 대화 길어짐 |

## Phase 3: 굴복 루트 — 핵심 메커니즘

### 목표
단둘이 있을 때 약점 협박 + 성적 강제 → 복종 수치 상승.

### 구현 항목

#### 3-1. "단둘이" 판정
- [ ] `is_alone_with(player_id, npc_id)` 헬퍼 함수
  - `get_units_at_location()`으로 현재 위치 캐릭터 목록
  - 플레이어 + 대상 NPC만 있으면 True
- [ ] UI에 "(단둘이)" 표시 (Situation에서)

#### 3-2. 약점 이벤트 (캐릭터별 복종 부스터)

기존 인프라 활용: 자위 발각(self_comfort), 성인용품(17종), Sound 전파, 발각 리액션

**세라 약점:**
- 자위 발각: 밤 순찰 후 혼자 방에서 자위 중 플레이어가 목격
  → 인프라: `_handle_self_comfort` + `ROMANCE_DISCOVERY_REACTIONS`
  → 효과: 약점 잡힘 (협박 선택지 등장), 복종 +15
- 숨겨둔 성인용품 발견: 세라 방 뒤지기 → 성인용품 발견
  → 인프라: 오브젝트 검색 액션 + 아이템 발견 이벤트
  → 효과: 대화에서 언급 가능 → 복종 +10
- 부상/약화 시 돌봐주기: 사냥 중 부상 → 플레이어가 간호
  → 효과: 심리적 우위, 반발 -10

**리나 약점:**
- 호기심으로 성인용품/성적 콘텐츠에 관심: 몰래 보다 걸림
  → 순수한 만큼 수치심 극대화, 복종 +15
- 술/미약: 밀라가 만든 약초주를 몰래 마시고 취함
  → 판단력 저하, 저항 감소 (일시적 반발 -20)
- 악몽/공포: 밤에 무서워서 떨고 있을 때 접근
  → 의존감 형성, 호감 +5 / 복종 +5

**밀라 약점:**
- 플레이어에 대한 호감 들킴: 밀라가 플레이어를 몰래 챙기는 것을 다른 NPC가 지적
  → 밀라가 부정하지만 동요, 플레이어가 이를 이용
- 과거 트라우마: 특정 상황에서 무력해짐 (단서를 통해 발견)
  → 심리적 우위, 복종 +10
- 밀라의 비밀 일기: 방에서 발견 → 내면의 갈등이 적혀 있음
  → 협박 소재, 복종 +10 / 반발 +5

**공통 약점:**
- 미약/수면제: 요리에 타기 (밀라가 요리 담당이라 재료 접근 필요)
  → 일시적 무력화, 특수 행위 가능
  → 위험: 들키면 신뢰 대폭 하락 + 게임오버
- 음주: 저녁에 술 권유 → 취한 상태에서 저항력 감소

### 약점 이벤트 발동 조건
```
약점 이벤트는 "자연스럽게" 발생하되, 플레이어 행동이 트리거:
  - 자위 발각: 밤 시간 + 해당 NPC 방 문 앞에 도달 (on_reach)
  - 성인용품: 해당 NPC 방에서 "뒤지기" 액션 (단둘이 X, NPC 부재 시)
  - 술/미약: 인벤토리에 재료 보유 + 요리/음료 제작 + NPC에게 제공
  - 부상/공포: 시간대/날씨 조건 + NPC 상태 조건 (자동 발생)
```

#### 3-3. 강제 행위 액션
- [ ] "단둘이"일 때만 표시되는 액션 추가 (actions 필터링)
- [ ] 약점 발동 후 "협박/위협" 선택지 등장
- [ ] 강제 성행위 시작 조건 (복종 임계치별로 가능 행위 확장)
- [ ] 복종 증가 로직 (기존 romance 시스템의 복종 증가 활용)

#### 3-3. 발각 시스템
- [ ] 행위 중 다른 NPC가 on_reach/on_meet으로 도착 시 발각
- [ ] 발각 판정: Sound 전파 시스템 활용 (소리 → 호기심 → 이동)
- [ ] 발각 결과:
  - 밀라가 발각: 눈감아줌 (호감 > 30일 때), 아니면 게임오버
  - 리나/세라가 발각: 게임오버 이벤트
- [ ] 게임오버 이벤트: 대화 → 추방 묘사 → 타이틀/리로드

#### 3-4. 다수결 굴복
- [ ] 리나 + 밀라가 플레이어 편일 때 (호감 or 복종 충분)
- [ ] 세라에게 다수결 이벤트 트리거 가능
- [ ] 세라 반발하지만 굴복 → 세라 복종 대폭 증가

### 체크리스트
- [ ] 단둘이 판정 정확성 (3명 이상이면 액션 숨김)
- [ ] NPC 도착 시 발각 이벤트 발생 확인
- [ ] 발각 → 게임오버 흐름 확인
- [ ] 밀라 눈감아줌 조건 확인
- [ ] 복종 수치 증가/감소 밸런스 확인
- [ ] 약점 이벤트: 자위 발각 (밤 + NPC 방 on_reach) 동작 확인
- [ ] 약점 이벤트: 성인용품 발견 (NPC 부재 + 뒤지기) 동작 확인
- [ ] 약점 이벤트: 술/미약 (제작 + 제공) 동작 확인
- [ ] 약점 이벤트: 부상/공포 (자동 발생 조건) 동작 확인
- [ ] 약점 발동 후 협박 선택지 등장 확인
- [ ] 약점 플래그가 세이브/로드에서 유지되는지 확인

### 테스트
```
1. 단둘이 상황 만들기 (Frozen 모드로 NPC 배치)

7. NPC 외출 중 방 뒤지기 → 성인용품 발견 확인
```

## Phase 4: 알파 판정 + 챕터 1 종료

### 목표
플레이어가 '알파' 조건 달성 시 챕터 1 종료.

### 알파 조건 (안)

```python
def check_alpha_status():
    """3명 모두의 인정이 필요"""
    for name in ["세라", "밀라", "리나"]:
        trust = get_prop(player, f"관계:{name}:신뢰") or 0
        submission = get_prop(player, f"관계:{name}:복종") or 0
        affection = get_prop(player, f"관계:{name}:호감") or 0

        # 신뢰 루트: 높은 신뢰 + 호감
        trust_ok = trust >= 10 and affection >= 60
        # 굴복 루트: 높은 복종
        submission_ok = submission >= 70

        if not (trust_ok or submission_ok):
            return False
    return True
```

### 구현 항목
- [ ] `check_alpha_status()` 함수 구현
- [ ] 주기적 체크 (on_time_elapsed or 퀘스트 완료 후)
- [ ] 알파 달성 이벤트 시퀀스 (축하/인정/굴복 대사)
- [ ] 챕터 1 → 챕터 2 전환 호출
- [ ] 챕터 2 스켈레톤 (최소한의 initialize)

### 체크리스트
- [ ] 신뢰 루트로 알파 달성 가능 확인
- [ ] 굴복 루트로 알파 달성 가능 확인
- [ ] 혼합 (세라=굴복, 밀라=신뢰, 리나=신뢰) 가능 확인
- [ ] 알파 달성 → 챕터 전환 정상 동작 확인
- [ ] 전환 후 플레이어 데이터 보존 확인

## Phase 5-B: 페이 합류

### 목표
떠돌이 상인 페이를 저택 거주 NPC로 전환. 상인 기능 유지 + 일반 생활 패턴.

### 합류 경로

| 경로 | 조건 | 효과 |
|------|------|------|
| 거래 신뢰 | 호감 60+ 거래 다수 | 자발적, 반발 없음 |
| 위기 구출 | 숲에서 습격당한 페이 구출 이벤트 | 은혜, 빠른 합류 |
| 거래 조건 | 알파 달성 후 "전속 상인" 제안 | 실용적 판단 |
| 협박 | 성인용품 판매 비밀 | 반발 높음 |
| 빚 관계 | 외상 거래 → 갚을 때까지 체류 → 정착 | 자연스러운 전환 |

### 기술 구현: 별도 클래스 방식

**이유**: FayeAgent는 상인 전용 (텔레포트/리셋/영업대기). BaseAgent와 양립 어려움.

```
faye.py (기존) — Faye + FayeAgent (상인 모드, 수정 없음)
faye_resident.py (신규) — FayeResident(Faye) + FayeResidentAgent(BaseAgent)
```

**FayeResident**:
- Faye 상속 → 대사/리액션/외모 재사용
- actions: 상인 기능(거래/매입) + 일반(대화/선물/심부름) 모두 포함
- 거주 전용 props 추가

**FayeResidentAgent (BaseAgent 상속)**:
- survival/needs/temperature 자동 등록 (일반 NPC 생활)
- 스케줄: 외출(물자조달) → 저택 내 영업 → 자유시간 → 수면
- 기존 상인 스케줄(요일별 텔레포트)은 사용하지 않음

**합류 시 전환 절차**:
1. 상인 Faye 삭제 (unit 제거)
2. FayeResident 스폰 (저택에 instantiate)
3. 관계 props 이관 (호감/복종/반발 등)
4. 방 배정 (기존 빈 방 or 건축 시스템으로 신규 방)

### 체크리스트
- [ ] FayeResident 클래스 생성 (Faye 상속)
- [ ] FayeResidentAgent 스케줄 정의
- [ ] 상인 기능 (거래/매입) 거주 모드에서 동작 확인
- [ ] 합류 이벤트 시퀀스 (최소 1경로)
- [ ] 전환 시 prop 이관 정상 확인
- [ ] 거주 후 일반 생활 패턴 (식사/수면/욕구) 동작 확인
- [ ] 기존 상인 Faye가 합류 전에는 정상 동작 확인 (기존 코드 미수정)
