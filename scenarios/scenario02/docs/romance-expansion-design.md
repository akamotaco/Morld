## 설계 원칙: 3축 능력치 (공격/방어/내성)

**캐릭터 능력치는 역할별로 분리 — 중복 기능 금지**:

| 축 | 성격 | 주 사용처 |
|----|------|---------|
| **근력** (`근력` prop) | 공격적 | 강간(`resolve_action_mode` forced 판정), 물리적 제압 |
| **체력** (`생존:체력` prop) | 방어적 | 탈출(`calculate_escape_chance`), 저항 지속 |
| **자제심** (`성격:자제심` prop) | 정신 내성 | 트랜스 진입 방어, 세뇌/약물 저항, 수치심 모디파이어 |

**의미**: 각 축은 독립적인 "당하는 방식"에 대응 — 물리/지속/정신. 한 축을 키우면 다른 축은 상대적으로 약해지는 트레이드오프 가능 (Phase 2 탤런트에서 확장).

## 0. 핵심 설계 원칙 (기획 우선)

> 이 원칙들은 Phase 계획보다 상위에 있으며, 모든 구현 결정을 제약한다.

### 0.1 단일 시스템 원칙 (Unified Base)

**모든 NPC는 동일한 스탯/행위/게이트 구조를 공유한다.**

- 랜덤 생성된 Tier 3 NPC부터 핵심 S02 8인 Tier 1까지 **스탯 스키마 동일**
- 게이트 공식 (3-path: 호감/복종/성욕) **동일하게 적용**
- 31개 궤적 아크타입 **전원 진입 가능**
- 액션 카테고리 (애무/도구/삽입/SM/강제/데이트/일상) **전원 접근**

**금지**: Tier별로 별도 로맨스 시스템을 만들지 않는다. 베이스는 단 하나.

### 0.2 Tier 오버라이드 증강 모델 (Augmentation, not Replacement)

**Tier 차이 = "커스터마이즈 깊이"**, 시스템 차이가 아님.

| Tier | 대사 | 이벤트 | 탤런트 | 퀘스트 |
|---|---|---|---|---|
| **Tier 3** (랜덤) | 아키타입 톤 템플릿 자동 생성 | 스탯 기반 자동 트리거만 | 아키타입 기본값 | 없음 |
| **Tier 2** (네임드 조연) | Tier 3 + 고유 대사 일부 override | 고유 이벤트 몇 개 추가 | 고유 탤런트 조합 | 소규모 |
| **Tier 1** (핵심 8인) | Tier 2 + 풀 오리지널 대사 | 전용 이벤트 시나리오 | 세밀 튜닝 | 주요 스토리 |

**패턴**: override lookup → 없으면 Tier 3 베이스로 fallback. (현 Hybrid 대화 엔진의 Tier 구조와 동일)

- 랜덤 NPC도 **31개 궤적 모두 자연 발생** (대사만 아키타입 톤)
- Tier 2+ NPC는 **독점 대사/이벤트로 개성 부여**, 하지만 시스템은 동일
- **신규 Tier 1 추가 = 기존 베이스 + override 파일** (시스템 재작성 아님)

### 0.3 역할 대칭 원칙 (Symmetry)

**플레이어와 NPC는 역할 구분 없이 subject/object 교환 가능**.

- 플레이어에게 NPC가 가진 모든 스탯 존재 (성욕/수치심/자제심/경험/처녀/탤런트 등)
- AI 행동 루프 역방향 작동 (NPC가 플레이어를 대상으로 think)
- 게이트 공식은 actor/target 매개변수만 받음 (플레이어 하드코딩 금지)

### 0.4 era TW는 참고, morld는 superset

**축소하지 않고 확장한다.**

- era TW 검증된 설계 요소 차용 (자제심/수치심/성별기호/각인 등)
- era에 없는 영역 적극 도입 (NTR/NTL/플레이어 피해/시뮬 자생 아크타입)
- 31개 궤적 중 era 직접 대응은 ~15개, 나머지 16개는 morld 고유 확장

### 0.5 기획 우선, 구현 차후

**올바른 기획 없이 코드 수정하지 않는다.** 현재 우선순위:

1. ✅ 설계 문서 (era 분석 / 확장 계획 / 궤적 공간)
2. ⏳ 스탯 네임스페이스 확정
3. ⏳ 아키타입 ↔ 탤런트 기본값 매핑
4. ⏳ Tier 오버라이드 포맷 명세
5. → **이후** Phase 0 구현 진입

    사용정도:  0 (없음) / 1 (단일) / 2 (이중)

- 삽입 부위(V/A/P)는 기본 단일 (도구 병용 제외)
- TFLAG로 전역 상태 추적 (MASTER의입사용중/손사용중/...)

→ **3인 이상 시나리오는 "한 중심 대상 × 여러 참가자의 부위 분담" 구조**로 모델링.

### Phase 1.6.1: 트랜스 상태 통합 (2026-04-24 완료)

**배경**: Phase 1.6 autonomy 진입 게이트를 "복종 OR 호감"으로 두었으나, 사용자 지적 —
**함락이 아니어도 성적 흥분이 충분하면** 자발 행동이 자연스럽다. 기존
`npc_thrust_trance` 진입도 성욕만 본다. 이를 **통합된 트랜스 상태**로 재편.

#### 1.6.1.1 `상태:트랜스` prop (0~100)

산출 공식 (비대칭 방어 전용 — Phase 1.8.1에서 개정):
```
base = (성욕 + 절정게이지) / 2
defense_factor = max(0.1, 1.0 - max(0, 자제심 - 50) × 0.02)
base × defense_factor
+ 트랜스:외부   # 외부는 자제심 우회
→ clamp 0~100
```

**자제심 방어 표**:
| 자제심 | factor | 방어율 |
|-------|-------|------|
| 0~50 | 1.0 | 없음 |
| 70 | 0.6 | 40% |
| 80 | 0.4 | 60% |
| 100 | 0.1 | 90% |

설계 원칙: 자제심은 **정신 공격 내성** 축. 높으면 자연 흥분에 의한
트랜스 진입을 강하게 방어하지만, 강한 외부 자극(세뇌·약물)은 우회 가능.

임계값:
- **트랜스 ≥ 60 (TRANCE_ENTRY)**: 흥분 트랜스 — 페르소나 억제 풀림
- **트랜스 ≥ 80 (TRANCE_DEEP)**: 깊은 트랜스 — 자발성 극대 (저항 약화는 후속)

#### 1.6.1.2 `트랜스:외부` 가산 축 (스켈레톤)

정신 교란 상태(술/약물/최면/세뇌)를 **통합 축**으로 처리하기 위한 공용 prop.
현 단계에서는 prop 정의만 도입 (실제 buff 부여 로직은 후속).
Option B (통합 축) 설계 결정을 완료.

#### 1.6.1.3 기존 시스템 통합

**`npc_thrust_trance` 진입** (romance.py):
- 트랜스 ≥ 60이면 `entry_arousal` −20, `entry_gauge` −10
- 자제심 낮은 NPC (seductive 등)는 낮은 성욕에서도 자연스럽게 진입

**Phase 1.6 autonomy 진입**:
- **복종/호감 게이트 완전 제거**
- 새 게이트: 트랜스 ≥ 60 + 쿨다운
- 의미: 관계 라벨과 무관하게 성적 흥분이 충분하면 자발 행동

#### 1.6.1.4 함수 API (`romance_dynamics`)

| 함수 | 용도 |
|------|------|
| `compute_trance_level(unit_id)` | 수치 계산 (저장 X) |
| `update_trance_level(unit_id)` | 재계산 + prop 저장 |
| `is_in_trance(unit_id, threshold=60)` | 진입 임계 조회 |
| `is_in_deep_trance(unit_id)` | 깊은 트랜스 조회 |

#### 1.6.1.5 테스트 커버리지

신규 11개 dynamics 테스트 (`TestTranceLevel`):
- 공식 검증 (baseline/자제심 영향/외부 가산/clamp)
- 저장 분리 (compute는 저장 X, update만 저장)
- 임계값 판정 (TRANCE_ENTRY / TRANCE_DEEP)

### Phase 1.8: 트랜스 상태 대사/수치 분기 (2026-04-24 완료)

**배경**: 트랜스 상태에서 NPC가 일반 캐릭터 톤을 유지하면 부자연스럽다.
깊은 트랜스는 유아퇴행·인간어 상실·의성어 위주. 또한 의식이 흐리므로
관계 기억(호감/반발)은 약화되고 몸(복종/쾌락/경험치)은 더 강하게 각인됨.

#### 1.8.1 수치 계수 (`compute_trance_multipliers`)

`romance_dynamics.py`에 트랜스 레벨별 효과 배율 함수 추가. `apply_effects`가
모드 배율(forced 등)과 **곱셈 합성**.

| 스탯 | 60~79 (trance) | 80+ (trance_deep) | 의미 |
|-----|---------------|-------------------|------|
| 호감 | ×0.6 | ×0.3 | 정신 기억 약화 |
| 반발 | ×0.6 | ×0.3 | 저항 의식 흐림 |
| 복종 | ×1.2 | ×1.5 | 몸 각인 강화 |
| 성욕/욕망 | ×1.1 | ×1.3 | 쾌락 루프 가속 |
| 절정 게이지 | ×1.2 | ×1.5 | 오르가즘 임박 가속 |
| 경험치 (부위별) | ×1.2 | ×1.5 | era 快楽 가속 (허들 낮추기) |

#### 1.8.2 era 快楽 호환성

era 시리즈의 `快楽` (쾌락 누적) 개념은 morld의 **기존 `경험:{부위}` + `복종`
할인 + 감도 배율 조합**으로 이미 표현 가능. 새 prop 불필요.

- 통합 쾌락 = `sum(경험:{부위})` — 필요 시 파생 함수로 제공
- 허들 낮추기 = Phase 0.5 `복종` 할인 + Phase 1 `get_sensation_level` 배율
- 조교 가시화 = 부위별 감도 레벨 상승

→ `era-series-analysis.md` §7.2의 "쾌락 누적 스탯 도입 고려"를 "**기존 경험치로 커버됨**"으로 갱신.

#### 1.8.3 대사 접두어 시스템

`_get_mode_reaction` 조회 순서 확장:

1. **트랜스 접두어 우선** (`trance_deep:{action}` > `trance:{action}`)
2. 모드 접두어 (`forced_{action}` 등)
3. 기본 반응
4. **공통 트랜스 fallback 풀** (`_GENERIC_TRANCE`, `_GENERIC_TRANCE_DEEP`)

공통 fallback 풀은 캐릭터 전용 trance 대사가 없을 때 사용. 의성어 위주:
- `_GENERIC_TRANCE`: "...하아... 아...", "...응... 헉..."
- `_GENERIC_TRANCE_DEEP`: "...아우... 으아...", "...히잉... 아앙..."

**캐릭터 샘플**: 유키에만 `trance:start` / `trance_deep:start` 추가.
나머지 5명은 후속 슬라이스 (캐릭터별 아키타입 톤으로 확장).

#### 1.8.4 테스트 커버리지

신규 8개 dynamics 테스트 (`TestTranceMultipliers`):
- 트랜스 0/60/80 구간별 배율 검증

- 정신(호감/반발) 약화 vs 몸(복종/절정/경험) 증폭 분리

### Phase 1.9: 복종 고도화 → 자제심 침잠 (2026-04-24 완료)

**배경**: 함락된 NPC(복종 高)가 기본 자제심을 그대로 유지하면 부자연스럽다.
era 조교 서사 — "몸이 먼저 굴복하고 정신이 뒤따른다" — 를 반영하여 복종 누적 시 **실질 자제심**이 점차 무너지도록 설계.

#### 1.9.1 `get_effective_restraint(unit_id)` 파생 함수

```
raw = 성격:자제심 (아키타입 기본값 fallback)
erosion = max(0, 복종 - 60) × 0.75
effective = max(0, raw - erosion)
```

**감쇠 표** (기본 자제심 80 기준):
| 복종 | 감쇠 | 실질 자제심 | 효과 |
|-----|------|----------|------|
| 0~60 | 0 | 80 | 방어 유지 |
| 70 | -7.5 | 72 | 방어 약화 시작 |
| 80 | -15 | 65 | 방어 무너지는 중 |
| 100 | -30 | 50 | 방어 완전 소실 (함락) |

**복종 임계 60**: Phase 1.5의 `get_submission_label`이 "충성"으로 분류하는 지점.
라벨 전환이 실제 스탯 효과와 일치.

#### 1.9.2 적용 범위 (옵션 B — 트랜스 + availability)

**트랜스 방어** (`compute_trance_level`):
- 기존 `성격:자제심` 직접 조회 → `get_effective_restraint` 경유
- 함락 NPC는 트랜스 방어가 소실되어 자연 흥분만으로도 깊은 트랜스 진입 가능

**availability_score** (`get_restraint_modifier`):
- 자제심 점수 페널티도 실질 자제심 기반
- 함락되면 행위 점수 페널티 자연 감소 → 가용 행위 범위 확장
- 효과: 함락 NPC는 저항 없이 고난도 행위도 가능

**미적용 범위**:
- 수치심 모디파이어 (`get_shame_modifier`)에는 raw 자제심 유지 — 수치심과 함락은 축이 달라 독립 유지

#### 1.9.3 테스트 커버리지

신규 10개 dynamics 테스트:
- `TestEffectiveRestraint` 7개: 복종 구간별 감쇠 검증 (0/50/60/70/80/100/floor)
- `TestTranceInfluencedByCorruption` 3개: 함락 시 트랜스 방어 소실 → 깊은 트랜스 cascade

### 9.3 불필요 — 제거 또는 미도입

> **원칙 재확인**: morld는 ero 게임이 아니다. 연애 시뮬레이션의 **자연스러움**이 목표이며, era의 explicit 세밀화는 대부분 불필요. 다만 시뮬레이션 상호작용성을 높이는 세밀함은 유지.

**era에서 가져오지 않을 것**:
- TALENT 1075 전체 — morld는 **~30개 핵심만**
- exp.csv 85 항목 → morld는 **~20개만** (부위 + 주요 행위 + 체위별 절정 + 조교/출산)
- 무자각 경험 (60-65) — **제외**
- Mark 시간각인/성장 — Phase 5+로
- 연령 축 (-1 아이) — **제외, 성인만**
- 탄막 전투 / 카지노 — 별개 시스템, **제외** (morld는 고유 전투/경제)

**유지 — 상호작용적 시뮬레이션에 기여**:
- **체위별 절정경험 (101-110)**: 정상위/후배위/기승위/대면좌위/배면좌위 × V/A = 10종 유지.
  `경험:{체위}{orifice}절정`. 체위별 차별성이 행위 시스템의 재미 요소. 체위 해금/선호도 조건에 활용.
- **시간정지**: S02에 **이미 `frozen.md` 시스템 존재** (Frozen 상태). era와 다른 맥락이지만 핵심 기능은 비슷. 제거하지 않고 기존 시스템 활용. 향후 유사 기능 확장 여지.
- **후타나리 = 양기 보유 단순 플래그**: 별도 로직 분기 없음. 단순히 `기관:남성기=1, 기관:여성기=1` 플래그 동시 보유로 처리. 성별기호 탤런트는 별개로 동작. 특수 경로 아님.
- **감금/매음 — 별도 시스템 미구현, 기존 시스템 조합**:
  - 감금 = 위치 제한 (텔레포트 차단) + bed_owner 제거 + 행동 제약 플래그
  - 매음 = 화폐 거래 이벤트 + 평판 prop + 공공 장소 접근
  - 별도 "감옥 모듈" / "매음굴 모듈" 만들지 않고 **조합으로 자연 발생**

**기존 morld에서 제거할 것**:
- ~~`관계:{p}:욕망`~~ — Phase 0에서 제거 확정

**우선순위 낮춤 (Phase 5+ or 스킵)**:
- ㉚ 정신 조작 → S04로
- ㉛ 정체 숨김 → Phase 5+ 서사 플래그
- ⑨ 정신 붕괴 접근로 → Phase 2 구현, 기본 비활성
- 다인 (3+) → Phase 4

### 9.4 계보 시스템 (Lineage)

**출산 결과를 prop으로 영구 보존 + 계보 추적**.

현재 `pregnancy.py`의 부분 구현:
- 아이에 `부모:어머니` / `부모:아버지` prop 존재
- 어머니에 `상태:아이아버지` / `상태:아이아버지id` 존재 (임신 중 추적용)

**보강 설계**:

```
# 아이 관점 (출생 시 영구 설정)
관계:부:{father_name} = father_unit_id
관계:모:{mother_name} = mother_unit_id

# 부모 관점 (출산 시 추가, 다자녀 가능)
관계:자녀:{child_name} = child_unit_id  # 복수 prop 패턴 (bed_owner 다수 보유와 동일)
```

**시사점**:
- "다자녀" 오버레이는 별도 스탯 아님 → **자녀 prop 개수가 곧 자녀 수**
- 계보 추적 자동화: `get_children(unit_id)`, `get_parents(unit_id)` 헬퍼
- 근친 감지 가능 (같은 부모 공유 시 형제/자매)
- NTR 서사에서 친부 확정 가능 (`관계:부:*` 조회)
- 손자/세대 확장 자연 (자녀 NPC가 또 자녀 낳으면 계보 연장)

**구현 Phase**:
- Phase 0 또는 1에서 기존 `pregnancy.py` 출산 핸들러에 계보 prop 추가
- 비용 낮음 (기존 구조 확장)

### 9.6 결론

- **공통 필수**: 8 스탯 + 3-path 게이트 + 플레이어 대칭 + 각인 시스템 + 계보 prop
- **핵심 확장**: 자제심/수치심/애정/탤런트 ~30개
- **유지 결정**: 체위별 절정경험(상호작용), 시간정지(S02 기존), 후타나리(양기보유 플래그), 감금/매음(조합 발생)
- **제거 확정**: era 과도 세밀화(무자각/연령/탄막/카지노 등) + morld 욕망 prop
