### 2.12 **다인조교 (3인 이상 동시 참가)**

`ERB/다인조교/나눠먹기.ERB` 분석:

**메커니즘**: **부위별 점유 추적**
```
몸사용중[MASTER][부위] = {
    사용정도:  0 (없음) / 1 (단일) / 2 (이중)
    사용자:    누가 사용하는지 (다수 가능)
}
```

**추적 부위**: 입 / 손 / C(클리) / V(질) / A(항문) / B(가슴) / P삽입

**동시 참가 모델**:
- 한 대상에 여러 참가자가 **서로 다른 부위 동시 점유**
- 일부 부위(ex: 가슴)는 두 명이 한쪽씩 점유 (사용정도 2)
- 삽입 부위(V/A/P)는 기본 단일 (도구 병용 제외)
- TFLAG로 전역 상태 추적 (MASTER의입사용중/손사용중/...)

→ **3인 이상 시나리오는 "한 중심 대상 × 여러 참가자의 부위 분담" 구조**로 모델링.

## 5. S02 구현 계획 (Phase 1~6)

### Phase 0: 즉시 수정 (당장 실행)
**`관계:{p}:욕망` 완전 제거**
- 게이트: `상태:성욕`(독립)으로 이관
- 할인: `get_effective_affection_req` 파라미터 재정의
- 이벤트 modify_prop: `상태:성욕`으로 리다이렉트
- 디버그 버튼: 라벨 정리 ("상태성욕 +20")
- 테스트 및 문서 업데이트
- 예상 영향: 14 참조처 수정

### Phase 1: 억제 이중축 도입
**자제심 × 수치심**
- 신규 prop: `성격:자제심` (0-100), `상태:수치심` (0-100)
- 기본값: 아키타입별 설정 (순수/절제 → 자제심 고, 방종 → 자제심 저)
- 게이트 공식:
  ```
  action_threshold = base
                     + 자제심 × α (내면)
                     + 수치심 × β × 관객계수 (사회)
                     - 성욕 × γ (촉진)
  ```
- 관객계수: location 내 타 NPC 존재 여부 + 관계 친밀도로 계산

### Phase 2: 성향 탤런트 체계
**Talent 시스템 이식**
- 신규 네임스페이스: `성향:{key}` (영구 또는 느린 변동)
- 핵심 탤런트: 담력/태도/자존심/츤데레/정조/저항/쾌감응답/도착적/새드/마조/성별기호
- 아키타입별 기본 탤런트 매핑 (8개 캐릭터 * ~12 탤런트)
- 각 커맨드/게이트 공식에 탤런트 보정 계수 반영

### Phase 3: 행위 카테고리 확장
**현재 스킨쉽 액션 → Train.csv 370종 규모로 분류**
- 카테고리 체계 도입: 애무/도구/삽입/SM/강제/데이트/일상/특수
- 현재 `romance_actions.py`의 ACTION_DEFS 재설계
- 각 액션에 해금 조건 (호감/복종/자제심/탤런트/경험)
- 실행 효과 (탤런트별 보정, 부위별 경험 누적)

### Phase 4: 다인 시나리오 지원
**부위별 점유 모델**
- 신규 네임스페이스: `점유:{부위}:{속성}` — 사용정도/사용자
- `romance_scene` 상태 확장: 참가자 배열 + 부위 분담
- 새로운 액션 카테고리: 다인 전용 (69/파이즈리펠라/교대삽입 등)
- UI: 참가자 선택 및 부위 할당

### Phase 5: NTR/NTL + 플레이어 대칭 스탯
**morld 고유 확장 (era 미구현 영역)**
- 질투 탤런트 구현 (Talent 84)
- `관계:{a}:충성:{b}` / `관계:{a}:질투:{b}` 스탯
- 플레이어 본인 스탯 풀세트:
  - `플레이어:상태:성욕` / `플레이어:상태:수치심` / `플레이어:처녀:{부위}` / `플레이어:경험:{부위}`
  - `플레이어:성격:자제심` / `플레이어:성향:{key}`
- NTR 이벤트: 관찰자 목격 + 증거 시스템 + 발각 판정
- NTL: 명시적 허용 플래그 + 참여도 스탯
- 역방향 지배 (NPC가 플레이어를 대상으로 행위)

### Phase 6: S04 이식

- **C. 하이브리드** — 기본값은 python, 런타임 변경은 prop
