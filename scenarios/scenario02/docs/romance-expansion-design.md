## 0. 핵심 설계 원칙 (기획 우선)

> 이 원칙들은 Phase 계획보다 상위에 있으며, 모든 구현 결정을 제약한다.

### 0.1 단일 시스템 원칙 (Unified Base)

**모든 NPC는 동일한 스탯/행위/게이트 구조를 공유한다.**

- 랜덤 생성된 Tier 3 NPC부터 핵심 S02 8인 Tier 1까지 **스탯 스키마 동일**
- 게이트 공식 (3-path: 호감/복종/성욕) **동일하게 적용**
- 31개 궤적 아크타입 **전원 진입 가능**
- 액션 카테고리 (애무/도구/삽입/SM/강제/데이트/일상) **전원 접근**

**금지**: Tier별로 별도 로맨스 시스템을 만들지 않는다. 베이스는 단 하나.

### 0.2 Tier 오버라이드 증강 모델 (Augmentation, not Replacement)

**Tier 차이 = "커스터마이즈 깊이"**, 시스템 차이가 아님.

| Tier | 대사 | 이벤트 | 탤런트 | 퀘스트 |
|---|---|---|---|---|
| **Tier 3** (랜덤) | 아키타입 톤 템플릿 자동 생성 | 스탯 기반 자동 트리거만 | 아키타입 기본값 | 없음 |
| **Tier 2** (네임드 조연) | Tier 3 + 고유 대사 일부 override | 고유 이벤트 몇 개 추가 | 고유 탤런트 조합 | 소규모 |
| **Tier 1** (핵심 8인) | Tier 2 + 풀 오리지널 대사 | 전용 이벤트 시나리오 | 세밀 튜닝 | 주요 스토리 |

**패턴**: override lookup → 없으면 Tier 3 베이스로 fallback. (현 Hybrid 대화 엔진의 Tier 구조와 동일)

- 랜덤 NPC도 **31개 궤적 모두 자연 발생** (대사만 아키타입 톤)
- Tier 2+ NPC는 **독점 대사/이벤트로 개성 부여**, 하지만 시스템은 동일
- **신규 Tier 1 추가 = 기존 베이스 + override 파일** (시스템 재작성 아님)

### 0.3 역할 대칭 원칙 (Symmetry)

**플레이어와 NPC는 역할 구분 없이 subject/object 교환 가능**.

- 플레이어에게 NPC가 가진 모든 스탯 존재 (성욕/수치심/자제심/경험/처녀/탤런트 등)
- AI 행동 루프 역방향 작동 (NPC가 플레이어를 대상으로 think)
- 게이트 공식은 actor/target 매개변수만 받음 (플레이어 하드코딩 금지)

### 0.4 era TW는 참고, morld는 superset

**축소하지 않고 확장한다.**

- era TW 검증된 설계 요소 차용 (자제심/수치심/성별기호/각인 등)
- era에 없는 영역 적극 도입 (NTR/NTL/플레이어 피해/시뮬 자생 아크타입)
- 31개 궤적 중 era 직접 대응은 ~15개, 나머지 16개는 morld 고유 확장

### 0.5 기획 우선, 구현 차후

**올바른 기획 없이 코드 수정하지 않는다.** 현재 우선순위:

1. ✅ 설계 문서 (era 분석 / 확장 계획 / 궤적 공간)
2. ⏳ 스탯 네임스페이스 확정
3. ⏳ 아키타입 ↔ 탤런트 기본값 매핑
4. ⏳ Tier 오버라이드 포맷 명세
5. → **이후** Phase 0 구현 진입

```

    사용정도:  0 (없음) / 1 (단일) / 2 (이중)
```

- 삽입 부위(V/A/P)는 기본 단일 (도구 병용 제외)
- TFLAG로 전역 상태 추적 (MASTER의입사용중/손사용중/...)

→ **3인 이상 시나리오는 "한 중심 대상 × 여러 참가자의 부위 분담" 구조**로 모델링.

## 5. S02 구현 계획 (Phase 1~6)

### Phase 0: 즉시 수정 (당장 실행)
**`관계:{p}:욕망` 완전 제거**
- 게이트: `상태:성욕`(독립)으로 이관
- 할인: `get_effective_affection_req` 파라미터 재정의
- 이벤트 modify_prop: `상태:성욕`으로 리다이렉트
- 디버그 버튼: 라벨 정리 ("상태성욕 +20")
- 테스트 및 문서 업데이트
- 예상 영향: 14 참조처 수정

### Phase 0.5: 공식 단순화 + 점수 합산 인프라 ✅ (2026-04-22 완료)

애정행위와 강제 행위 통합을 위한 기반 작업. era TW의 `GET_SUCCESS_RATE` 패턴에서
차용한 **"베이스라인 + 모디파이어 점수 합산"** 모델을 도입.

**변경**:
- **제압 공식 단순화**: `calculate_force_chance` — 근력차만 (체격/hp 제거)
- **탈출 공식 재작성**: `calculate_escape_chance(target, actor)` —
  체력차 베이스라인 + 복종/반발/성욕 모디파이어

### 9.3 불필요 — 제거 또는 미도입

> **원칙 재확인**: morld는 ero 게임이 아니다. 연애 시뮬레이션의 **자연스러움**이 목표이며, era의 explicit 세밀화는 대부분 불필요. 다만 시뮬레이션 상호작용성을 높이는 세밀함은 유지.

**era에서 가져오지 않을 것**:
- TALENT 1075 전체 — morld는 **~30개 핵심만**
- exp.csv 85 항목 → morld는 **~20개만** (부위 + 주요 행위 + 체위별 절정 + 조교/출산)
- 무자각 경험 (60-65) — **제외**
- Mark 시간각인/성장 — Phase 5+로
- 연령 축 (-1 아이) — **제외, 성인만**
- 탄막 전투 / 카지노 — 별개 시스템, **제외** (morld는 고유 전투/경제)

**유지 — 상호작용적 시뮬레이션에 기여**:
- **체위별 절정경험 (101-110)**: 정상위/후배위/기승위/대면좌위/배면좌위 × V/A = 10종 유지.
  `경험:{체위}{orifice}절정`. 체위별 차별성이 행위 시스템의 재미 요소. 체위 해금/선호도 조건에 활용.
- **시간정지**: S02에 **이미 `frozen.md` 시스템 존재** (Frozen 상태). era와 다른 맥락이지만 핵심 기능은 비슷. 제거하지 않고 기존 시스템 활용. 향후 유사 기능 확장 여지.
- **후타나리 = 양기 보유 단순 플래그**: 별도 로직 분기 없음. 단순히 `기관:남성기=1, 기관:여성기=1` 플래그 동시 보유로 처리. 성별기호 탤런트는 별개로 동작. 특수 경로 아님.
- **감금/매음 — 별도 시스템 미구현, 기존 시스템 조합**:
  - 감금 = 위치 제한 (텔레포트 차단) + bed_owner 제거 + 행동 제약 플래그
  - 매음 = 화폐 거래 이벤트 + 평판 prop + 공공 장소 접근
  - 별도 "감옥 모듈" / "매음굴 모듈" 만들지 않고 **조합으로 자연 발생**

**기존 morld에서 제거할 것**:
- ~~`관계:{p}:욕망`~~ — Phase 0에서 제거 확정

**우선순위 낮춤 (Phase 5+ or 스킵)**:
- ㉚ 정신 조작 → S04로
- ㉛ 정체 숨김 → Phase 5+ 서사 플래그
- ⑨ 정신 붕괴 접근로 → Phase 2 구현, 기본 비활성
- 다인 (3+) → Phase 4

### 9.4 계보 시스템 (Lineage)

**출산 결과를 prop으로 영구 보존 + 계보 추적**.

현재 `pregnancy.py`의 부분 구현:
- 아이에 `부모:어머니` / `부모:아버지` prop 존재
- 어머니에 `상태:아이아버지` / `상태:아이아버지id` 존재 (임신 중 추적용)

**보강 설계**:

```
# 아이 관점 (출생 시 영구 설정)
관계:부:{father_name} = father_unit_id
관계:모:{mother_name} = mother_unit_id

# 부모 관점 (출산 시 추가, 다자녀 가능)
관계:자녀:{child_name} = child_unit_id  # 복수 prop 패턴 (bed_owner 다수 보유와 동일)
```

**시사점**:
- "다자녀" 오버레이는 별도 스탯 아님 → **자녀 prop 개수가 곧 자녀 수**
- 계보 추적 자동화: `get_children(unit_id)`, `get_parents(unit_id)` 헬퍼
- 근친 감지 가능 (같은 부모 공유 시 형제/자매)
- NTR 서사에서 친부 확정 가능 (`관계:부:*` 조회)
- 손자/세대 확장 자연 (자녀 NPC가 또 자녀 낳으면 계보 연장)

**구현 Phase**:
- Phase 0 또는 1에서 기존 `pregnancy.py` 출산 핸들러에 계보 prop 추가
- 비용 낮음 (기존 구조 확장)

### 9.6 결론

- **공통 필수**: 8 스탯 + 3-path 게이트 + 플레이어 대칭 + 각인 시스템 + 계보 prop
- **핵심 확장**: 자제심/수치심/애정/탤런트 ~30개
- **유지 결정**: 체위별 절정경험(상호작용), 시간정지(S02 기존), 후타나리(양기보유 플래그), 감금/매음(조합 발생)
- **제거 확정**: era 과도 세밀화(무자각/연령/탄막/카지노 등) + morld 욕망 prop
- **Phase 재정렬**: 0 → 1(억제축) → 2(탤런트/각인) → 3(액션확장) → 4(다인) → 5(제3자+대칭+자생) → 6(S04)

설계 공간은 정제됐지만, **구현 스코프 여전히 크다**. 각 Phase 진입 전 세부 체크리스트 별도 작성 권장.
