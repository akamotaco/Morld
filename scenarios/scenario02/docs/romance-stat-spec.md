## 0. 핵심 용어: 성격 vs 페르소나 (독립 축)

morld에는 **두 개의 독립된 인격 축**이 존재한다. 같은 캐릭터가 서로 어긋나는 조합을 가질 수 있고, 이 mismatch 자체가 캐릭터 개성이 된다.

| 축 | 영향 | 성격 | 값 | 관할 |
|---|---|---|---|---|
| **성격 (`성격:*`)** | **외형적 — 행동** | 세부 7 trait | 담력/태도/응답/자존심/츤데레/정조/명랑 | 행위 게이트, NPC think, 묘사 |
| **페르소나 (`아키타입`)** | **내면적 — 대사** | 카테고리 10종 | stoic/cheerful/timid/fierce/innocent/cold/gentle/seductive/proud/devoted | 대사 톤 템플릿 |

### 왜 분리하는가

두 축이 **독립적**이기 때문에 mismatch가 가능하다:

**예시 — "대범한 성격 + 소심한 페르소나"**:
- 성격: 담력=1, 자존심=0, 정조=-1 → **행동**: 치마를 살짝 들춘다 (대범)
- 페르소나: timid → **대사**: "보...보지 말라고, 이... 바보야..." (소심)

통합 축이었다면 "대범하게 행동 + 대범하게 말한다" / "소심하게 행동 + 소심하게 말한다"의 두 패턴뿐. 분리하면 **10 페르소나 × 3^7 성격 = 21,870 조합**.

### 매핑은 프리셋 수준만

- Tier 3 랜덤 생성: 페르소나 선택 → 성격 **기본값** 프리셋 로드 → variance
- Tier 2+ 네임드: 페르소나 + 성격 override dict (위 예시 같은 의도적 mismatch 구현)
- 런타임: 페르소나와 성격은 **독립 변동**

### 페르소나 prop 이름 주의

`persona.py` 엔진은 `아키타입` prop 이름 사용 (기존 10종 리스트). 개념적으로 "페르소나"와 동일. 본 문서는 개념은 **페르소나**, 기존 코드 식별자는 **아키타입** 유지.

### 성격 → 이벤트 → 대사 매개 관계

성격이 대사 내용을 **직접** 결정하지 않는다. 매개 레이어가 있다:

```
성격·상태 매칭 → 이벤트 발동 → 페르소나 템플릿에서 대사 선택
```

- **성격** = 어떤 이벤트가 일어나는가
- **페르소나** = 일어난 이벤트를 어떻게 말하는가

예시 — 같은 이벤트, 페르소나별 다른 대사:
```
조건: 성격:츤데레=1 AND 호감 ≥ 50 AND 반발 ≥ 30
  → "표리 반전" 이벤트 발동
  
페르소나별 대사:
  proud (츤데레 trait 1) : "아... 좋, 좋아. 너만 특별히..."  (inner_bias 풍부)
  fierce                : "흥! 생각해 볼게."                (담백)
  stoic                 : "...그래."                          (미니멀)
```

**꼬임 방지 메커니즘**:
- 전역 이벤트 레지스트리 (priority 정의)
- Intent fallback chain (페르소나가 특정 intent 없으면 상위 fallback)
- Turn counter jitter + 캐릭터별 ring buffer (중복 감소, 경량 유지)

### 기존 `성격` (단일 prop) — Deprecated

과거 `성격` (단일 문자열 prop, "낙천적"/"과묵" 등 14종)은 S04 Tier 3 랜덤 생성에만 사용되던 페르소나 유도 메커니즘. **단일 스키마 이식 방침에 따라 deprecated**.

- **공존 없음**: S02에서 본 문서의 체계(`아키타입` + `성격:*` + `성향:*`) 확립
- **S04 이식 시 (Phase 6)**: character_randomizer 재작성 — 페르소나 직접 선택, `성격:*` 7 trait 직접 생성
- **최종 상태**: `성격` (단일) prop 제거, `PERSONALITY_TO_ARCHETYPE` 매핑 제거

## 1. 네임스페이스 체계

### 1.1 원칙

1. **역할 대칭**: 플레이어와 NPC 모두 동일 네임스페이스 사용. `플레이어:*` 같은 별도 공간 없음.
2. **시맨틱 분리**: 변화 속도와 영향 범위로 구분.
3. **기존 morld 컨벤션 존중**: `관계:`, `상태:`, `생존:`, `경험:`, `처녀:`, `can:` 유지.
4. **prop 키 소문자 지양**: 한국어 키 유지 (가독성).

### 1.2 변화 속도 스펙트럼

```
[순간] ←────────────────────────────────→ [영구]

상태 < 관계(활성) < 성향 < 성격 < 각인 ≈ 경험
매 scene    이벤트로      조교로       주요 사건     임계 달성 시
변동        점진 변화      느린 변화    변화 가능     획득 (불가역)
```

### 1.3 네임스페이스 일람

| 네임스페이스 | 의미 | 변화 속도 | 예시 키 |
|---|---|---|---|
| `관계:{target}:*` | A→B 관계 (target 이름별) | 중간 | 호감, 복종, 반발, 애정, 충성, 질투, 부, 모, 자녀 |
| `상태:*` | 순간 상태 (scene/day-level) | 빠름 | 성욕, 흥분, 절정, 분노, 무드, 피로 |
| `성격:*` | 고정 성격 (거의 불변) | 매우 느림 | 담력, 태도, 자존심, 응답, 츤데레, 정조, 명랑 |
| `성향:*` | 성적·행동 성향 (조교로 변동) | 느림 | 자제심, 수치심, 쾌감응답, 새드, 마조, 도착, 성별기호 |
| `경험:*` | 누적 경험 (영구 증가) | 단방향 | C경험, 정상위V절정, 키스경험, 출산경험 |
| `각인:*` | 영구 각인 (임계 획득) | 불가역 | 쾌락, 고통, 반발, 굴복, 시간 |
| `기관:*` | 신체 기관 보유 | 불변 | 남성기, 여성기, 자궁, 가슴 |
| `처녀:{부위}` | 미경험 플래그 | 단방향 | 구강, 음부, 항문 |
| `생존:*` | 생존 스탯 (기존) | 빠름 | 체력, 기력, 포만감, 갈증 |
| `can:{action}` | 행위 허용 플래그 (기존) | 런타임 제어 | can:hold_hands, can:errand |
| `pregnancy:*` | 임신 관련 (기존 확장) | 주기적 | 주차, 수정일 |

**기타 morld 기존 네임스페이스** (로맨스 무관, 참고):
- `heat:*` (온도), `storage:*` (보관), `bed_owner:*`, `wardrobe_owner:*`,
- `퀘스트:*`, `chapter:*` 등

## 2. 세부 스펙

### 2.1 관계 (`관계:{target}:*`)

target은 **유닛 이름**(한국어). 키 중복 가능 (bed_owner 패턴: `관계:리나:호감`, `관계:유키:호감` 공존).

| 키 | 범위 | 의미 | 변화 계기 |
|---|---|---|---|
| `관계:{t}:호감` | 0~100 | 긍정 감정 | 대화/선물/도움/배신(-) |
| `관계:{t}:복종` | 0~100 | 굴복·예속 | 강제 경험/조교 |
| `관계:{t}:반발` | 0~100 | 부정 감정 | 강제/거부 누적 |
| `관계:{t}:애정` | 0~100 | 연애 감정 (상위) | 호감 高 + 이벤트 |
| `관계:{t}:충성` | 0~100 | 배신 저항 | 파트너 관계 성립 시 |
| `관계:{t}:질투` | 0~100 | 제3자 개입 반응 | 파트너 다른 이에 접근 목격 |
| `관계:부:{t}` | unit_id | 친부 (영구) | 출산 시 설정 |
| `관계:모:{t}` | unit_id | 친모 (영구) | 출산 시 설정 |
| `관계:자녀:{t}` | unit_id | 자녀 (다수) | 출산 시 추가 |

### 2.2 상태 (`상태:*`)

| 키 | 범위 | 의미 | 변화 계기 |
|---|---|---|---|
| `상태:성욕` | 0~100 | 순간 흥분 게이지 | 자극/시간/행위/약물 |
| `상태:흥분` | 0~100 | (예비) scene 중 고조도 | scene 진행 |
| `상태:절정` | 0~100 | 절정 게이지 | 자극 누적 |
| `상태:무드` | -100~100 | 감정 기분 | 이벤트 반응 |
| `상태:분노` | 0~100 | 분노 | 배신/모욕 |
| `상태:아이아버지` | name | 임신 시 친부 이름 (기존) | 수정 판정 |
| `상태:아이아버지id` | id | 친부 ID (기존) | 수정 판정 |

### 2.3 성격 (`성격:*`)

**범위**: -1 / 0 / 1 (era 스타일) 또는 0~100 (morld 세부화). **권장: -1/0/1 3단계** (선택 단순화).

| 키 | -1 | 0 | 1 |
|---|---|---|---|
| `성격:담력` | 겁쟁이 | 보통 | 다부짐 |
| `성격:태도` | 솔직함 | 보통 | 반항적 |
| `성격:응답` | 얌전 | 보통 | 거만 |
| `성격:자존심` | 낮음 | 보통 | 높음 |
| `성격:츤데레` | - | 아님 | 츤데레 |
| `성격:정조` | 관심없음 | 보통 | 엄격 |
| `성격:명랑` | 음침 | 보통 | 명랑 |
| `성격:기분파` | - | 아님 | 기분파 |

### 2.4 성향 (`성향:*`)

**범위**: 성격과 동일 (-1/0/1) 또는 강도가 중요한 경우 0~100.

| 키 | 범위 | 의미 |
|---|---|---|
| `성향:자제심` | 0~100 | 내면 억제 (성욕→행동 전환 제어) |
| `성향:수치심` | 0~100 | 사회 억제 (관객 민감도) |
| `성향:쾌감응답` | -1/0/1 | 쾌감에 부정/보통/솔직 |
| `성향:새드` | 0~100 | 가학 성향 강도 |
| `성향:마조` | 0~100 | 피가학 성향 강도 |
| `성향:도착` | 0~100 | SM·비일상 성향 |
| `성향:성별기호` | -1~3 | -1 양도 / 0 이성애 / 1 남성기피 / 2 여성기피 / 3 인간불신 |
| `성향:무관심` | 0~1 | 성적 무관심 (무성애) |
| `성향:감정결여` | 0~1 | 전체 감정 둔화 |
| `성향:자위중독` | 0~100 | 자위 의존도 |
| `성향:노출벽` | 0~100 | 노출 선호 |
| `성향:집착` | 0~100 | 얀데레 경향 |

### 2.5 경험 (`경험:*`)

| 키 | 의미 |
|---|---|
| `경험:C`, `경험:V`, `경험:A`, `경험:B`, `경험:M` | 부위별 누적 |
| `경험:C절정`, `경험:V절정` 등 | 부위별 절정 횟수 |
| `경험:정상위V절정`, `경험:후배위V절정`, `경험:기승위V절정`, `경험:대면좌위V절정`, `경험:배면좌위V절정` | 체위×V |
| `경험:정상위A절정`, ... (5종) | 체위×A |
| `경험:키스`, `경험:펠라`, `경험:파이즈리`, `경험:삽입` 등 | 행위별 |
| `경험:조교`, `경험:레즈`, `경험:게이` | 특수 누적 |
| `경험:출산`, `경험:강간`, `경험:자위` | 결과 누적 |

### 2.6 각인 (`각인:*`)

임계 도달 시 영구 부여. 일반적으로 0/1 flag (또는 레벨).

| 키 | 의미 | 획득 조건 (예시) |
|---|---|---|
| `각인:쾌락` | 쾌락각인 | 쾌락경험 누적 임계 (era Juel) |
| `각인:고통` | 고통각인 | 고통경험 누적 임계 |
| `각인:반발` | 반발각인 | 반발 누적 임계 |
| `각인:굴복` | 굴복각인 | 복종 누적 + 절정 경험 |
| `각인:시간` | 시간각인 | 시간정지 경험 |
| `각인:성장` | 성장각인 | 임신/출산 등 주요 이벤트 |

### 2.7 기관 (`기관:*`)

| 키 | 값 | 의미 |
|---|---|---|
| `기관:남성기` | 0/1 | 남성 성기 보유 |
| `기관:여성기` | 0/1 | 여성 성기 보유 |
| `기관:자궁` | 0/1 | 자궁 보유 (임신 가능 여부) |
| `기관:유방` | 0/1 | 유방 발달 (수유 가능) |

**표준 조합**:
- 남성: `기관:남성기=1` + 나머지 0
- 여성: `기관:여성기=1, 기관:자궁=1, 기관:유방=1`
- 후타나리: `기관:남성기=1, 기관:여성기=1, 기관:자궁=0 또는 1, 기관:유방=1`
- 중성: 전부 0 (희귀 케이스)

`scenarios/common/python/engine/romance/stats.py` (신규 예정):

```python
# 관계
get_affection(actor, target) / set_affection / modify_affection
get_submission / get_rebellion / get_love / get_loyalty / get_jealousy

# 상태
```

### 6.7 변동 규칙

**성격 (`성격:*`)**:
- 기본 거의 불변
- 변화 계기: 주요 서사 이벤트 (구원 성공/붕괴/각성)
- 예: ⑯ 구원 성공 → `성격:명랑` -1 → 0 변화 가능

**성향 (`성향:*`)**:
- 조교/경험으로 점진 변화
- 0~100 타입: 경험치와 비례 누적
- -1/0/1 타입: 임계 경험으로 단계 이동
- 예:
  - `성향:자제심` → 강제 경험 누적 시 감소
  - `성향:도착` → SM 경험 누적 시 상승
  - `성향:수치심` → 반복 공개 노출 시 감소
  - `성향:마조` → 피가학 쾌락 누적 시 상승 (㉔ 변태각성 경로)

### 6.8 성격:* 영향 영역 (7가지)

성격:*는 **행동에만 영향** (대사는 페르소나 전담). 스탯 기반 창발 모델 — 궤적 레이블 게이트 없음.

**1. 행위 게이트 보정**
`effective_threshold = base + 담력×5 + 자존심×8 + 정조×10 + 태도×3 + …`

**2. 스탯 변동 계수**
- 복종 증가: 자존심 -1 → ×1.5 / 1 → ×0.5
- 반발 증가: 담력 -1 → ×0.7 / 1 → ×1.3
- 무드 회복: 명랑 1 → ×1.5

**3. NPC think 의사결정**
- 담력 -1 → 위험 활동 회피
- 태도 1 → 지시 거부 확률 ↑
- 정조 1 → 성적 접근 스스로 차단

**4. 묘사 분기 (대사 아닌 서술 텍스트)**
- 명랑 -1 → "표정이 어둡다"
- 담력 -1 → "손이 떨리고 있다"
- 자존심 1 → "고개를 꼿꼿이 세우고 있다"

**5. 스탯 패턴 기반 이벤트 발동 조건**
이벤트는 궤적 레이블이 아닌 **스탯·트레이트 조건으로만** 발동.

*예시 — 표리 반전 이벤트*:
```
조건: 성격:츤데레 = 1 AND 호감 ≥ 50 AND 반발 ≥ 30
발동: 대사 템플릿 "내면 고백" + 호감 가속 + 반발 감소
```

궤적으로 보면 "②" 같아 보이지만 **게임 내 레이블 없음**. 플레이어가 사후 관찰로 읽을 뿐.

**6. 각인 획득 임계**
- `각인:반발`: 정조 1 → 임계 낮음 (쉽게 각인)
- `각인:굴복`: 자존심 1 → 임계 높음

**7. 액션 카테고리 접근성**
- 정조 1 + 호감 < 70 → 애무 카테고리 전면 잠금
- 태도 1 → 강제 액션에 저항 체크 강화

### 7.7 Variance 적용 규칙 (Tier 3 랜덤 생성)

```
성격 (-1/0/1):
  60% 기본값 유지
  20% +1 shift (clamp [-1, 1])
  20% -1 shift (clamp [-1, 1])

성향 (0~100):
  기본값 ± 20 uniform random
  clamp [0, 100]

성향 (-1/0/1):
  70% 기본값 유지
  15% +1 / 15% -1 (clamp)

성향 (0/1 flags):
  80% 기본값 유지
  20% flip (0 ↔ 1)

성별기호 (-1~3):
  85% 0 (이성애)
  5%  -1 (양도)
  5%  1 (남성기피)
  5%  2 (여성기피)
  (3 인간불신은 특수, 수동 지정만)
```

### 7.8 S02 6 NPC 초기 프리셋 (Phase 1 도입 시)

Phase 1에서 전 NPC에 `성향:자제심/수치심` 필수 부여. 페르소나 기본값 + 개별 override.

| NPC | 페르소나 | 자제심 | 수치심 | 비고 |
|---|---|---|---|---|
| 리나 | cheerful | **50** | **70** | cheerful 기본(40/30) + 겁 많음 override |
| 유키 | timid | 70 | 80 | timid 기본값 유지 |
| 밀라 | gentle | 60 | 60 | gentle 기본값 유지 |
| 세라 | stoic | 70 | 50 | stoic 기본값 유지 (마조 성향은 Phase 2) |
| 페이 | proud | 80 | 70 | proud 기본값 유지 |
| 엘라 | cold | 60 | 40 | cold 기본값 유지 (감정결여/자기애는 Phase 2) |

Phase 2부터 성격 7 trait + 성향 성애·병리 추가. 페이(proud)는 츤데레 아님 — proud→devoted 서사적 반전 구조.

**Lina (cheerful 베이스, 겁 많은 밝은 소녀)**:

```python
Lina.archetype = "cheerful"
Lina.personality_override = {
```

```python
Faye.archetype = "fierce"

    "명랑": -1,       # fierce 기본 0 → -1 (차가운 표정 기본)
```

### 7.10 적용 흐름

```
[NPC 생성]
  1. 아키타입 결정 (랜덤 또는 지정)
  2. 위 매핑표에서 기본값 dict 로드
  3. variance 적용 (Tier 3) OR override dict 병합 (Tier 2+)
  4. 최종값으로 prop 설정 (성격:*, 성향:*)

[런타임]
  - 스탯 변동 시 기존 prop 값 기준 계산
  - 성격:* 변경은 거의 없음 (주요 서사 이벤트만)
  - 성향:* 변경은 조교/경험으로 점진적
```

### 7.11 Phase별 도입

| Phase | 도입 |
|---|---|
| Phase 0 | persona.py 매핑은 기존대로, 새 성격:*/성향:* prop 미사용 |
| Phase 1 | `자제심`, `수치심` 프리셋 적용 — 위 표의 두 컬럼만 |
| Phase 2 전반 | 성격 7 trait 프리셋 적용 |
| Phase 2 후반 | 성향 성애 8개 프리셋 적용 |
| Phase 3 | 성향 병리·특수 + 매력·조교 9개 프리셋 적용 |
| Phase 4~5 | 성향 체질·욕구 4개 프리셋 적용 |

각 Phase 도입 시 기존 NPC는 **마이그레이션** (아키타입 기반 기본값 설정), 신규 생성은 처음부터 프리셋 반영.

### 7.12 Phase 2 전반 착수 체크리스트 (2026-04-24 추가)

성격 7 trait(`성격:담력/태도/응답/자존심/츤데레/정조/명랑`) 도입 시 건드릴 지점.

**코드 수정 지점**:
1. **아키타입 기본값 dict** (`romance_core.py` 또는 신규 `romance_traits.py`):
   - `ARCHETYPE_PERSONALITY_DEFAULT` — 10 아키타입 × 7 trait 기본값 (§7.2 내용)
2. **기본값 조회 헬퍼**:
   - `get_personality_value(unit_id, key)` — raw prop 우선, 없으면 아키타입 기본값
   - `get_effective_personality(unit_id, key)` — Phase 1.9 복종 침잠 패턴 유사 (필요 시)
3. **게이트 공식 통합** (`romance_core.calculate_availability_score`):
   - §6.8 영향 영역 1 "행위 게이트 보정" 구현
   - `baseline += 담력×5 + 자존심×8 + 정조×10 + 태도×3`
4. **스탯 변동 계수** (복종·반발 변동 시):
   - §6.8 영향 영역 2: 자존심 -1 → 복종 gain ×1.5, 담력 -1 → 반발 gain ×0.7 등
5. **NPC think 의사결정** (`think/` 핸들러):
   - 담력 -1 → 위험 활동 회피
   - 태도 1 → 지시 거부 확률 ↑
   - 정조 1 → 성적 접근 자동 차단
6. **묘사 섹션** (`assets/base.py`):
   - `_DESCRIBE_PERSONALITY_*` 신규 섹션 추가 (명랑 -1 → "표정 어둡다" 등)
7. **prop 저장**: 기존 Character.instantiate()가 아키타입별 기본값 자동 주입
8. **테스트**: 기본값 조회 / 게이트 반영 / 변동 계수 / override 우선순위

**마이그레이션 전략**:
- Phase 1 패턴 재사용 — raw prop 없으면 아키타입 기본값 사용 (`get_restraint_value` 참조)
- 기존 NPC는 prop 없음 → 기본값 자동 적용
- 신규 NPC는 instantiate 시 명시 주입
- S02 6 NPC는 §7.8 프리셋 + §7.9 override를 asset 클래스에 정의

### 7.13 Phase 2 후반 착수 체크리스트

성향 성애 8개(`성별기호/쾌감응답/새드/마조/도착/노출벽/무관심/감정결여`).

**주요 적용 지점**:
1. **성별기호** — 이미 `gender.get_orientation_*` 존재 (연계 검토 필요)
2. **쾌감응답** — `stimulation.calc_gain`의 반발 factor와 유사하게 배율
3. **새드·마조** — 가해/피해 행위 시 쾌락 보정, 복종·반발 계수 조정
4. **도착·노출벽** — availability_score 모디파이어 (수치심 상쇄)
5. **무관심·감정결여** — 트랜스 진입 억제 (Phase 1.6.1 트랜스 공식에 factor)

### 7.14 구현 순서 제안

**Slice A (아키타입 기본값 인프라)**:

## 8. 묘사 시스템 로드맵

### 8.1 현재 상태

- 위치: `scripts/scenario02/python/assets/base.py` (~30개 dict, line 324~1273)
- 목록: `_FOCUS_*` (클릭 묘사) 12종 + `_DESCRIBE_*` (위치 묘사) 15종
- 파티션: 페르소나(아키타입) 중심, 조건(성욕/호감/mood) 분기
- 호출: `build_focus_rules(archetype, ...)` / `build_describe_rules(archetype, ...)` 빌더

### 8.2 한계

- **성격:* trait 미반영**: 현재 묘사는 페르소나만으로 분기. "대범한 성격 + 소심한 페르소나" mismatch 묘사 불가.
- **중복 데이터**: 페르소나별 유사 표현 반복 (예: "얼굴이 붉어졌다" 5개 페르소나 각각 다른 버전).
- **Hybrid 엔진과 분리**: 대사는 경량 yaml, 묘사는 dict 하드코딩 → 일관성 저하.

### 8.3 목표 (Phase 2 후반 ~ 3)

**중복 최소화 + 콘텐츠 추가 용이성**을 최우선으로 Hybrid 엔진에 편입.

구조:
```
dialogues/
├── common/
│   └── slots.yaml                   # 페르소나 무관 공통 slot pool
└── archetype_dialogues/{arch}/
    └── descriptions.yaml            # 신규 context
```

엔진 확장:
- Hybrid `trait_bias` 도입 (기존 `state_bias`와 별개)
- 템플릿 매칭 시 성격/성향 trait 거리 계산 → softmax 선택

예시:
```yaml
# dialogues/common/slots.yaml
face_flush: [볼이, 얼굴이, 볼과 귀가]
flush_degree: [살짝 붉어져, 빨갛게 달아올라, 발그레하게]
body_react: [시선을 피하고, 손가락을 만지작거리며, 입술을 달싹이며]

# dialogues/archetype_dialogues/timid/descriptions.yaml
intents:
  desire:
    templates:
      - pattern: "{face_flush} {flush_degree} 있다. {body_react}..."
        state_bias:
          성욕: 0.8
        trait_bias:
          성향:수치심: 0.7
          성격:담력: -1
      - pattern: "{face_flush} {flush_degree} 있지만, 시선은 정면을 향한 채 숨을 고르고 있다."
        state_bias:
          성욕: 0.8
        trait_bias:
          성향:수치심: 0.7
          성격:담력: 1    # mismatch 케이스
```

효과:
- 새 페르소나 추가 = 폴더 + 3~5 템플릿만 작성
- 공통 표현 (`face_flush` 등) 한 곳에서 관리
- 성격 trait이 자동으로 mismatch 케이스 분기

### 8.4 마이그레이션 계획

| Phase | 작업 |
|---|---|
| Phase 0~2 전반 | 기존 dict 유지. 새 스탯은 대사·행위에만 반영. |
| **Phase 2 후반** | Hybrid 엔진 `trait_bias` 지원 추가 |
| **Phase 2 후반** | 공통 slot pool 도입 (`common/slots.yaml`) |
| **Phase 2 후반** | 시험: 1개 페르소나(timid)의 `_FOCUS_DESIRE` + `_FOCUS_AFFECTION` yaml 변환 |
| **Phase 3 전반** | 자동 변환 스크립트 + 수동 튜닝으로 30 dict 전체 yaml 이관 |
| **Phase 3 전반** | `build_focus_rules/build_describe_rules` → Hybrid 호출로 전환 |
| **Phase 3 후반** | 기존 dict 제거 (~500 줄 삭제) |
| Phase 6 (S04 이식) | 단일 묘사 시스템 확정 |

### 8.5 비용 vs 이득

**1회 비용**:
- Hybrid 엔진 `trait_bias` 확장: ~200줄
- 공통 slot pool 설계: ~150줄 yaml
- 변환 스크립트: ~300줄 python
- 수동 튜닝: 3~5일 작업
- 기존 dict 제거: ~500줄 삭제

**지속 이득**:
- 페르소나 추가 비용: 80줄 → 5줄
- 새 감정/상황 추가: slot pool에 어휘만 추가
- 성격·페르소나 mismatch 자동 처리
- 대사 시스템과 구조 통일 → 유지보수성 향상
