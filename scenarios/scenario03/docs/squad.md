# 분대 시스템 (Squad System)

## 개요

탐사는 **분대(Squad)** 단위로 수행한다. 한 분대는 **4명**의 분대원(에이전트)으로 구성된다. 모든 분대원은 시리얼 번호로 식별된다 ([design.md](design.md) 4.2절 참조).

---

## 구현 기반: party.py

분대 시스템은 **신규 구현이 아니라** 시나리오02의 `party.py` (파티 시스템)을 확장하여 사용한다.

### 시나리오02 파티 ↔ 시나리오03 분대 대응표

| party.py (시나리오02) | 분대 시스템 (시나리오03) | 비고 |
|----------------------|----------------------|------|
| `Squad` 클래스 | 분대 | 동일 구조 |
| `Squad.leader_id` | 분대장 | 동일 |
| `Squad.members` (최대 3명) | 분대원 (3명 + 분대장 1명 = 4명) | 동일 |
| `Squad.player_directive` | 공세 레벨 | 리네이밍 + 확장 |
| `Order` 클래스 | 오퍼레이터 지시 | 동일 구조 |
| `Order.order_type` | 지시 유형 (follow/search/guard) | 동일 |
| `Order.priority` (-1.0~+1.0) | 수집↔전투 우선순위 | 동일 |
| `Order.stealth` (0.0~1.0) | 은신 수준 | 동일 |
| `leader_traits` (aggression, focus) | 분대장 성향 | 리더십/판단력/카리스마로 확장 |
| FSM CommandPhase | 명령 수행 단계 | 동일 |
| FSM StandbyPhase | 대기 단계 | 동일 |
| FSM LifePhase | 일상 생활 단계 | 동일 |

### 필요한 확장

| 항목 | 현재 (party.py) | 추가 필요 |
|------|----------------|----------|
| 대열 순번 (Rank) | 없음 (members는 순서 없는 리스트) | `{unit_id: {"rank": 1\|2\|3}}` 속성 추가 |
| 동조율 | 없음 | 관계 시스템 확장 (prop 기반) |
| 통신 두절 | CommandPhase → StandbyPhase 패스스루 | 통신 상태 prop 추가 |

### Player Directive → 공세 레벨

```python
# 시나리오02 (기존)
DIRECTIVES = ["auto", "search", "combat_stealth", "combat_normal",
              "combat_aggressive", "retreat", "wait"]

# 시나리오03 (확장) — 동일 구조, 네이밍 변경
AGGRESSION_LEVELS = {
    "retreat":           -2,   # 전면 후퇴
    "defensive":         -1,   # 방어 우선
    "hold":               0,   # 현 위치 유지
    "combat_normal":      1,   # 교전 허가
    "combat_aggressive":  2,   # 적극적 공격
}
```

## 분대 구성

### 기본 규칙

- **분대 인원:** 4명 (리더 1 + 멤버 3 = `MAX_MEMBERS=3` + leader)
- **역할 분배:** 자유 (권장 구성 있음)
- **분대장 지정:** 분대장 1명 필수

### 대열 순번 (Rank)

1D 전투 공간에서 분대원의 배치 위치. 전투의 핵심 전술 요소이다.

| 순번 | 위치 | 적합 역할 |
|------|------|----------|
| 1열 | 전위 | 돌격, 근접 전투 |
| 2열 | 중위 | 화력 지원, 중거리 |
| 3열 | 후위 | 저격, 의료/기술 지원 |

대열 교체(Swap)는 마이크로 턴 사이에 가능하나, 교체 중 무방비 상태. 전투 시스템 상세는 [combat.md](combat.md) 참조.

### 권장 구성

| 구성 | 역할 배분 | 적합한 탐사 |
|------|----------|------------|
| 균형형 | 돌격1 + 화력1 + 지원1 + 저격1 | 범용 |
| 돌격형 | 돌격2 + 지원1 + 저격1 | 전투 중심 |
| 잠입형 | 정찰2 + 지원1 + 해커1 | 정보 수집/우회 |

## 분대장 (Squad Leader)

### 역할

- 분대원 통솔
- 현장 판단 (오퍼레이터 통신 두절 시)
- 사기 유지

### 분대장 성향 (leader_traits 확장)

시나리오02의 `leader_traits`(aggression, focus)를 확장:

| 성향 | 시나리오02 기반 | 시나리오03 효과 |
|------|---------------|----------------|
| 공격성 (aggression) | `leader_traits.aggression` | 공세 레벨 해석에 영향 |
| 집중도 (focus) | `leader_traits.focus` | 목표 우선순위 결정 |
| 리더십 | **추가** | 분대원 사기 유지 효과 |
| 판단력 | **추가** | 통신 두절 시 자율 판단 품질 |
| 카리스마 | **추가** | 명령 수행률 |

## 분대 시너지

### 관계 기반 시너지

분대원 간 관계에 따른 효과 ([agent.md](agent.md) 관계 시스템 참조):

| 관계 상태 | 효과 |
|----------|------|
| 모두 친밀 | 협동 보너스 +20% |
| 적대 관계 존재 | 협동 패널티 -15% |
| 깊은 유대 쌍 | 해당 쌍 시너지 +30% |

### 동조율

분대원 간 친밀도. 너무 높으면 항명 발생 — 부상당한 동료를 구하기 위해 후퇴 명령을 무시하거나, 동료의 죽음에 공황 상태에 빠질 수 있다.

구현: 관계 시스템에 `동조율` prop 추가, 임계치 초과 시 FSM에서 명령 무시 로직.

## 분대 운영

### 분대 편성

- 탐사 전 분대 구성 (`party.py` API 사용)
- 분대원 상태 확인 (부상, 피로 등)
- 장비 배분 + 대열 순번 지정

### 분대 교대

- 연속 탐사 시 피로 누적
- 분대 단위 휴식 필요
- 최소 2개 분대 권장

---

## 통신 시스템

### 오퍼레이터 ↔ 분대

- 텍스트 로그 + 오디오 통신 기반
- 상황 보고 수신
- 명령 하달

구현: Dialog 시스템 + `Order` API

### 통신 두절 상황

- 전파 방해, 심층 구역 등
- 분대장 자율 판단으로 전환
- 일정 시간 후 자동 복귀/철수

구현: FSM 패스스루 — `CommandPhase.update()` returns `False` → `StandbyPhase`가 분대장 AI로 판단. 시나리오02의 기존 패턴과 동일.
