# S04 파이프라인 테스트 설계

> 상태: 설계 단계
>
> 목적: 게임 한 사이클(시작→영입→던전→전투→귀환→사망→리셋)의 전체 동작 검증

---

## 게임 형태

**자유도 높은 생활형 로그라이트**

| 요소 | 규칙 |
|------|------|
| 로그라이크 | 플레이어 사망 → 플레이어 리셋, 던전 리셋 |
| 로그라이크 | 플레이어 사망 → 플레이어+던전+숏컷 리셋 |
| 로그라이트 | 마을 발전 유지, NPC 관계 유지, 도감 유지 |

---

## 테스트 파이프라인

### Phase 1: 게임 시작

```
[테스트 항목]
1. 마을 초기화 (Region 0: 마을, Region 1: 필드)
2. 플레이어 랜덤 생성
   - 성별: 랜덤
   - 스탯: base_str/agi/vit/mnd 각 8~15 랜덤
   - 직업: 선택 (또는 랜덤)
   - 시작 위치: 마을 광장
3. 마을 NPC 초기 배치 (npc_generator)
   - 여관에 2~3명 초기 배치
4. 시스템 초기화 확인
   - survival 등록
   - economy 초기 소지금
   - erosion = 0
   - morality = +20 (기본)
   - fame = 0

[검증]
- get_header()에 "마을 광장", 시간, "밝음" 표시
- get_footer()에 HP/포만감 바 표시
- get_action_text()에 이동 선택지 표시
```

### Phase 2: 파티원 영입

```
[테스트 항목]
1. 여관으로 이동
2. NPC 목록 확인 (focus)
3. 파티 초대
   - 성공 조건: trust >= 20, morality 차이 < 60
   - 실패 조건: trust 부족, 성향 충돌
4. 파티 상태 확인
   - party.get_members() == [player, npc]
   - party.get_size() == 2

[검증]
- add_member 성공/실패 분기
- 파티원의 stat_tab 표시
- 파티원이 마을 NPC 목록에서 제거됨
```

### Phase 3: 던전 돌입

```
[테스트 항목]
1. 던전 입구(loc 7)로 이동
2. dungeon.enter_dungeon(floor=1) 호출
3. F1 생성 확인
   - 3~5개 방
   - 방마다 has_monster 플래그
   - Gate 연결 (선형)
4. 생물 스포너 등록 확인
5. 플레이어 위치: F1 첫 번째 방

[검증]
- 지도 탭에 던전 구조 표시
- 방 이동 가능
- 밝기: 층별 감소
```

### Phase 4: 전투 테스트

```
[테스트 항목]
1. has_monster == True인 방 진입
2. 적 생성 (generate_encounter)
   - F1 풀: BlindRat(군집), Fangdog(선공), Slimeworm(수비), Petraspider(잠복)
3. 전투 실행 (encounter_handler.start_encounter)
4. 결과 적용
   - HP 동기화
   - 침식 변동
   - 사기 변동
   - 드롭 아이템
5. 파티원 실신 처리
   - 일반 멤버: 파티 이탈
   - 플레이어: dungeon.reorganize()

[검증]
- 전투 로그 출력
- HP 변동 반영
- 드롭 아이템 인벤토리 추가
- 실신 시 파티 상태 변경
```

### Phase 5: 마을 귀환

```
[테스트 항목]
1. F1 입구 방으로 이동
2. dungeon.exit_dungeon() 또는 마을 출구 Gate
3. 마을 복귀 확인
   - 위치: 마을 광장 또는 던전 입구
4. 회복 행동
   - 구호소: HP 회복 (경제 연동)
   - 정화소: 침식 감소 (경제 연동)
   - 여관: 숙박 (장 휴식 → HP 100% + 이벤트)
5. 장비 구매/수리 (대장간)
6. 파티원 재영입 (이탈한 경우)

[검증]
- 마을 시스템 정상 동작
- 경제 잔액 변동
- 휴식 이벤트 발생 (기벽/탈주 판정)
```

### Phase 6: 게임오버 + 리셋

```
[테스트 항목]
1. 전투에서 플레이어 HP 0
2. party.handle_faint(player_id) 호출
3. dungeon.reorganize() 실행
4. 플레이어 구호소 텔레포트

[리셋 검증]
리셋되어야 하는 것:
  - 플레이어 스탯 → 기본값
  - 플레이어 장비 → 소실
  - 던전 구조 → 재생성
  - 소지금 → 절반
  - 침식 → 0
  - 파티 → 해산

유지되어야 하는 것:
  - 마을 건물/시설
  - NPC 관계 (trust/morale)
  - NPC 존재 (여관에 복귀)
  - 명성
  - 숏컷 해금 → 리셋 (로그라이크)
  - 도감 (발견한 생물)

[검증]
  - 리셋 후 마을에서 재시작 가능
  - NPC에게 말 걸면 기존 관계 유지
  - 숏컷 리셋 → F1부터 다시 시작
```
